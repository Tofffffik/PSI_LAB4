# Отчёт по лабораторной работе №4

Мобильное приложение «Курсы валют» (Android, Flutter).

## 1. Тема и обоснование

**Вариант Б**: конвертер валют из Лаб 3, перенесённый на мобильную
платформу и расширенный экранами сравнения за неделю и за месяц.

Тема выбрана, потому что требования к ней уже понятны после Лаб 3 (работа
без сети, обработка ошибок, валидация), и всё внимание можно отдать
новому: мобильной платформе, новому языку и аналитике.

## 2. Смена языка

| Лабораторная | Язык | Стек |
|--------------|------|------|
| Лаб 3 | C# | .NET 9, Windows Forms, затем WPF |
| Лаб 4 | **Dart** | Flutter 3.47, Material 3 |

Код Лаб 3 не переиспользован. Логика написана заново и устроена иначе:
другой источник данных (JSON вместо XML), ряд курсов за период вместо
курса на день, расчёт статистики, которого в Лаб 3 не было.

## 3. Источник исторических данных

**Frankfurter** (`api.frankfurter.dev`) — бесплатный API с курсами
Европейского центрального банка, без ключа. Один запрос возвращает весь
ряд за период:

```text
https://api.frankfurter.dev/v1/2026-09-14..2026-10-14?base=USD&symbols=EUR
```

Почему не источник из Лаб 3 (Национальный банк Молдовы): он отдаёт курс
только на одну дату, и для месячного графика понадобилось бы 30
запросов. Накопление данных в локальной базе с момента установки тоже
не подходит: к сдаче месячного графика просто не было бы.

Ограничения:

- **Нет молдавского лея** — ЕЦБ его не публикует. В списке 14
  распространённых валют.
- **Только рабочие дни.** За «последние 7 дней» на графике около 5
  точек, за месяц — около 22. Это сказано на экране.
- **Источник может вернуть предыдущий рабочий день** до начала периода —
  такие точки отбрасываются.
- **Кэш хранится отдельно для каждой пары и периода.** Без сети доступны
  только те пары и экраны, которые уже открывались с сетью.

## 5. Что ИИ сделал корректно и где ошибся

**Корректно с первой попытки:**

- вся логика на Dart: разбор ответа, статистика, валидация, репозиторий с
  откатом на кэш;
- 45 unit-тестов — все прошли при первом запуске, `flutter analyze` без
  замечаний;
- оба варианта интерфейса (простой и переработанный) собрались и
  заработали без исправлений кода.

**Ошибки и проблемы — почти все в окружении сборки, а не в коде:**

| № | Что произошло | Как исправлено |
|---|---------------|----------------|
| 1 | Первая сборка APK упала: в Android SDK не было NDK 28.2, а автоматическая установка через Gradle не сработала | NDK установлен вручную через новый `android sdk install` |
| 2 | ИИ сначала вызвал устаревший `sdkmanager` со старым синтаксисом пакета (`ndk;28.2...`) — команда не нашла пакет | найден новый синтаксис `ndk/28.2...` по справке инструмента |
| 3 | Сборка падала с ошибкой Kotlin «this and base files have different roots»: проект на диске D:, кэш пакетов Flutter на C: | в `android/gradle.properties` отключена инкрементальная компиляция Kotlin |
| 4 | Flutter потребовал «Режим разработчика» Windows для символических ссылок плагинов | включён вручную в настройках Windows (ИИ не меняет системные настройки) |
| 5 | Первая сборка длится несколько минут без вывода; её дважды прервали, приняв за зависание | в README добавлено предупреждение |
| 6 | При переименовании окна ИИ записал кириллицу прямо в `main.cpp` и закоммитил, не дождавшись результата сборки — сборка под Windows упала | заголовок записан через `\u`-экранирование, отдельный коммит |
| 7 | Эмулятора не было; загрузку образа через командную строку остановили, потому что не было видно прогресса | эмулятор создаётся в Android Studio, инструкция в README |

## 6. Работа с ИИ на новом языке

> **Этот раздел — ключевой вывод лабораторной, и он должен быть написан
> вами.** Ниже — наблюдения из этой работы, на которые можно опереться.
> Замените их своими словами и своим опытом: что вы понимали в коде на
> Dart, что приходилось переспрашивать, что было бы сложно объяснить на
> защите.

Наблюдения:

- **Язык оказался не главной трудностью.** Код на Dart заработал сразу,
  а почти всё время ушло на окружение: Android SDK, NDK, Gradle, Kotlin,
  режим разработчика Windows. В Лаб 1–3 на C# такого не было, потому что
  .NET-проект собирается одной командой.
- **ИИ хорошо переносит идеи, а не код.** Структура (разбор → статистика
  → репозиторий с кэшем → экраны) получилась похожей на Лаб 3, но
  написана заново под особенности Dart: `Future` вместо `Task`, records и
  `switch`-выражения, `FutureBuilder` в интерфейсе.
- **Ошибки окружения ИИ разбирает хуже, чем ошибки кода.** Сообщения
  Gradle длинные и неочевидные; правильная причина (разные диски C: и D:)
  нашлась по одной строке в середине стека.
- **Проверять за ИИ всё равно нужно.** Ошибка № 6 — пример: изменение
  выглядело тривиальным, но закоммичено до проверки сборки.
